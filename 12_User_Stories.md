# User Stories

| ID | Epic | User story | Priority |
|---|---|---|---|
| US-01 | Application | As an applicant, I want to save a draft so that I can complete the application later. | Should |
| US-02 | Application | As an applicant, I want field-level validation so that I can correct errors before submission. | Must |
| US-03 | Consent | As the bank, I want purpose-specific consent evidence so that data checks are initiated only under approved conditions. | Must |
| US-04 | KYC | As an operations analyst, I want to see KYC status and reason category so that I can resolve pending cases. | Must |
| US-05 | Bureau | As a credit analyst, I want a bureau response linked to the application so that I can assess creditworthiness using an approved source. | Must |
| US-06 | Decision | As a credit officer, I want policy outcome and reason codes so that I can understand the decision path. | Must |
| US-07 | Exceptions | As a reviewer, I want a prioritised exception queue so that I can work cases within agreed SLAs. | Must |
| US-08 | Controls | As a control owner, I want maker-checker for configured overrides so that one user cannot both initiate and approve restricted actions. | Must |
| US-09 | Offer | As an applicant, I want clear offer terms and KFS before accepting so that I can make an informed decision. | Must |
| US-10 | Disbursal | As an operations user, I want disbursal status reconciled so that customers are not told funds were sent before confirmation. | Must |
| US-11 | Notifications | As an applicant, I want milestone updates so that I know whether action is required. | Should |
| US-12 | Reporting | As a product owner, I want funnel and turnaround dashboards so that I can identify process bottlenecks. | Should |
