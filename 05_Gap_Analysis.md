# Gap Analysis

| Area | As-Is hypothesis | To-Be capability | Expected benefit |
|---|---|---|---|
| Application capture | Repeated entry / channel-specific forms | Common application data model and save/resume | Less re-keying |
| Completeness | Late discovery of missing fields | Real-time validation and document checklist | Better first-time-right |
| Consent | Evidence may be fragmented | Purpose-specific consent record with timestamp/version | Better traceability |
| KYC | Status held in separate workflow | Clear KYC status and exception reason integration | Fewer blind hand-offs |
| Bureau | Request / response status not visible to all roles | Controlled bureau request and response status | Better operational visibility |
| Decision | Policy checks and exceptions fragmented | Configurable rules workflow and reason codes | Consistent processing |
| Manual review | Email / spreadsheet routing | Role-based queue, SLA and maker-checker | Controlled exception handling |
| Customer updates | Inconsistent notifications | Event-driven milestone notifications | Better transparency |
| Reporting | Delayed operational MIS | Defined event model and KPI dashboard | Faster management action |
| Audit | Evidence spread across systems | Immutable / tamper-evident event history and access logs | Stronger auditability |

## Prioritisation
Must-have: consent evidence, KYC status, application validation, controlled decision routing, manual review, customer disclosures, audit trail and security controls.
Should-have: save/resume, queue ageing, operational dashboard, configurable notifications.
Could-have: advanced funnel analytics and channel-specific personalisation.
